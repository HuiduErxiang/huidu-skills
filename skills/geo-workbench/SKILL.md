# GEO 工作台

版本：0.3.1。

## 排障入口

用户要求解释采集失败、检查连接、输出日志或导出诊断时，先读 [排障协议](references/troubleshooting.md)，不要因此新建或继续采集任务。运行 `scripts/workbench.py diagnose --run latest` 获取当前证据；需要交付日志时加 `--output /绝对路径/diagnostics.json`，按环境要求记录文件创建。即使本地服务未启动，也会尝试只读导出已有 SQLite 日志。不能拿当前机器的状态解释同事机器过去的故障。

失败展示必须包含：平台和步骤、真实观察、原因确认程度、已脱敏工具错误、同事下一步、负责人排查方向及任务编号。没有具体证据时使用 `GEO_UNKNOWN`，禁止只给“采集连接中断”或把心跳超时等同于断连。工作台可复制排障信息、导出诊断 JSON；不自动发送给他人。

实际采集前读取 [排障协议](references/troubleshooting.md) 中的逐步回写规范。工作台无法直接截获聊天的浏览器工具错误；当前聊天必须在连接浏览器、打开页面、检查登录、输入关键词、读取联想、提交/读取 AI 等关键操作前后，按实际结果回写 `start/ok/error/wait` 日志。不要补造未记录的历史。

## 两组独立输入

搜索/社交平台只使用用户的关键词采集真实联想，不执行 AI 追问。AI 平台只使用用户自行填写的主设问（每行一条，1～20 条），按原文回答与追问；不得从搜索联想推导、自动填充或替换主设问。网页在创建研究时保存两组输入并同时生成两路任务，不要求先完成搜索。缺少主设问时让用户在网页填写，不自行选题。

每个平台回答全部主设问，并围绕第一个主设问独立请求 3 条澄清问题；搜索联想仅作为搜索平台的结果。两路可分别推进，一侧等待用户或失败时，不把它当成另一侧的前置条件。仍须遵守暂停状态和实际工具可用性。旧任务缺少主设问可在任务页手动补充；已有 AI 任务保留原题与来源记录，不覆写历史。

## 用户入口：先打开工作台，再让用户点击

用户说“用 GEO 技能”“打开 GEO 工作台”“研究某产品的 GEO”时，主动准备并打开工作台，不要求用户先找到网址、手动运行命令或创建网页。配套工作台已包含在本技能的 `assets/workbench/` 中。启动脚本自动定位，不依赖原开发电脑的路径；可用环境变量 `GEO_WORKBENCH_ROOT` 指定其他位置。需要 Python 3.9+ 以及当前聊天可用的浏览器或 Computer Use 工具。

1. 运行本技能的 `scripts/workbench.py prepare`，取得服务状态、工作台URL及打开前最新任务ID。
2. 若返回 needs_start，用 exec_command 在返回的 cwd 运行返回的 command（即 scripts/workbench.py start）。该命令在 macOS 使用 launchd，在其他系统使用脱离启动终端的进程，并把输出写入返回的 log_files；不要直接用短期终端会话运行 server.py 并宣称服务会持续运行。启动前后按环境要求记录数据库及服务日志文件的创建/变更。需要端口或后台服务权限时按工具要求请求；不绕过限制。再运行 prepare 确认服务可用。若返回 ready 直接复用，不重复启动。
3. 使用 `open_in_codex` 打开返回的本地URL；不可用时使用允许的浏览器入口。工具只返回queued不代表页面可用，需确认页面实际可访问。向用户说明“工作台已打开，请分别填写搜索关键词与 AI 主设问，再点击创建研究”。用户已明确提供的产品、关键词或主设问可预填；不替用户选择未授权的新研究或问题。
4. **保持当前聊天的执行回合，等待用户在网页点击。** 在prepare之前记录已有任务ID集合，使用scripts/workbench.py wait --after <prepare返回的newest_run> --timeout 45等待新任务；只接手本次打开后创建的任务。如果出现多个历史waiting_chat，核对created时间，不误跑旧任务。每次等待不超过50秒；用户在聊天补充信息时立即吸收。合理等待期间不要求用户再回聊天说“开始研究”。若用户长时间未创建或明确要求先停，说明当前没有持续监听，并让用户稍后回聊天继续；不得宣称结束回合后还在监听。
5. 新任务出现后读取[执行协议](references/runner.md)，由**当前聊天的 Computer Use**接手，进度、登录提示和结果回写网页。用户点击创建即为对所选产品、关键词和平台的执行指令，无需重复询问开始。
6. 所有步骤完成后打开该任务的HTML报告，提供独立文件。遇到需用户操作，先把具体操作写到网页，在本回合等待其点击继续；聊天已结束则必须如实提示需回到聊天续跑。

常驻后台的只是本地网页和存储服务，macOS 中由当前用户的 launchd 管理，不配置开机自启。采集仍由活跃聊天执行。不启动后台 codex 采集执行器，不继承或转移聊天外的浏览器权限。网页按钮负责保存用户意图；实际操作仍由活跃的当前聊天执行。暂停前后检查任务状态，不继续已暂停的任务。

采集抖音、快手、小红书、百度用户选中的平台；AI支持豆包、DeepSeek、千问、元宝、ChatGPT，按用户选择执行。平台是否可自动操作需实际验证，不把选项存在当成已验证兼容。

优先可用浏览器工具；网页读取失败时尝试桌面 Computer Use。桌面 Chrome 在本项目已实际跑通过小红书、豆包、DeepSeek。每次操作后读取最新状态，不复用过期索引。浏览器枚举标识可能变化，核对名称和类型。

所有任务状态和用户提示写回网页。遇到登录，在 task 更新中设 needs_user，说明具体平台和所需动作；用户在网页点击继续后，重新检查真实页面，不把点击当作登录成功。工具或系统必须使用原生确认时遵守该要求，网页不能替代权限机制。

每个平台记录联想原文、顺序、时间和证据；排除历史搜索、广告和UI文字。接口联想与网页登录联想分别标注。跨平台重复不能当成搜索量。联想结果不进入 AI 主设问，不据此推荐或自动选定 AI 问题。

每题新开会话，原样发送用户填写的主设问，不擅自添加产品名或改写问题。每个 AI 回答全部主设问，另做 1 次独立追问探索，仅围绕第一个主设问生成 3 条澄清问题。统一提示词由任务提供。保存完整回答、会话链接、可见模型和联网状态（不可见则未知）。不核验引用链接，按用户要求不打开引用页。

严格区分搜索联想、AI澄清、推演用户问题。没有真实响应不得标 done；失败、待采集的产品提及为未知。只在回答正文判断提及，排除侧栏聊天历史中的药名。不要把医疗内容转换为个人用药建议，研究不代表医学核验。

采集全部完成后服务自动生成独立HTML报告，网页提供查看和下载按钮。报告路径data/reports/{run_id}.html，预览GET /api/runs/{run_id}/report。报告参考用户示例，包含搜索来源、产品可见度、实际一层追问树、共性与异同、标记为待验证的用户问题推演和完整回答。不得为了仿照示例补造第二层或平台数据。引用不核验。

平台兼容性和已知限制见[平台实测记录](references/platforms.md)。工作台同步展示 `platform-status.json`；已配置不代表完整验证。
